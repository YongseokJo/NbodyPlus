## Objective

Analyze the profiling data collected in Plan 09-01 to identify the primary bottleneck and quantify load imbalance, documenting findings for Phase 10 optimization.

## Context

Plan 09-01 collected:
- Aggregated Performance Summary from console output
- Per-timer min/avg/max across MPI ranks
- Load balance ratios and warnings
- Throughput metrics for neighbor pairs

This plan analyzes that data to satisfy requirements:
- ANLZ-01: Profile data collected ✓ (from 09-01)
- ANLZ-02: Bottleneck identified with quantitative evidence
- ANLZ-03: Load imbalance quantified

<task id="2">
<title>Identify primary bottleneck</title>
<type>analysis</type>
<action>
Calculate percentage of total wall time for each timer category:

1. **Top-level breakdown:**
   - IrregularForce vs RegularForce vs FewBody
   - MPI communication overhead
   - Queue/scheduling overhead

2. **Irregular force breakdown (if dominant):**
   - NeighborLoop vs CMLoop vs Correction vs Predict
   - Pairs evaluated throughput

3. **Communication breakdown (if significant):**
   - WorkerRecvWait vs TaskDispatch vs SendComplete
   - QueueAssign vs QueueRun vs QueueWait

Identify the component taking the largest percentage of wall time.
Document the percentage and confidence in the finding.
</action>
<verification>
Primary bottleneck identified with percentage > 30% of total time.
</verification>
</task>

<task id="3">
<title>Quantify load imbalance</title>
<type>analysis</type>
<action>
For each timer category, record:
- Load balance ratio (max/avg)
- Which rank is slowest (max_rank)
- Which rank is fastest (min_rank)

Identify timers with ratio > 1.2 (significant imbalance).
Correlate imbalance with work distribution if possible.
</action>
<verification>
Load imbalance documented for all timers.
Worst imbalances identified.
</verification>
</task>

<task id="4">
<title>Generate optimization recommendations</title>
<type>analysis</type>
<action>
Based on findings, generate prioritized optimization targets for Phase 10:

**If irregular force dominates:**
- SIMD vectorization of neighbor loop
- Cache optimization for data access patterns
- Reduce neighbor list overhead

**If MPI communication dominates:**
- Batch sends to reduce message count
- Overlap computation with communication
- Reduce synchronization points

**If load imbalance dominates:**
- Improve work distribution algorithm
- Dynamic load balancing
- Work stealing

**If queue scheduling dominates:**
- Optimize assignment algorithm
- Reduce callback overhead
</action>
<verification>
At least one concrete optimization target identified with expected impact.
</verification>
</task>
