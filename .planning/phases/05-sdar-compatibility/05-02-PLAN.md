## Objective

Add SoA sync calls to `fb_initialization.cpp` to ensure particle data consistency when forming new FewBody groups. Sync from SoA to AoS (particles[]) before SDAR initialization so the AoS array has current data.

## Context

In `NewFBInitialization()`:
1. Member particles are read from `particles[]` array
2. Their positions/velocities are predicted and copied to SDAR's internal storage
3. CM particle is created and properties copied from members

With SoA as the source of truth, we need to ensure `particles[]` is synced from `particle_data` before these operations.

**Key insight from research**: SDAR copies particle data into its own `sym_int.particles` storage. The main `particles[]` array is accessed for:
- Member particle data (copied to SDAR)
- Neighbor list references (perturbers)
