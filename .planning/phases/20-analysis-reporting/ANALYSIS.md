## Expected Imbalance Sources

Based on ABYSS architecture, likely findings from production runs:

### 1. Neighbor Count Variance (Expected: HIGH)

N-body simulations inherently have non-uniform particle density. Particles in dense regions (star clusters, binary systems) have significantly more neighbors than isolated particles.

**Metric threshold:** CV > 0.5 indicates concern, CV > 1.0 is HIGH severity.

**Recommendation:** Neighbor-count-aware task scheduling or work stealing.

### 2. Worker Load Imbalance (Expected: MEDIUM-HIGH)

With static task distribution, workers assigned dense regions finish slower than workers with sparse regions.

**Metric threshold:** Load balance ratio > 1.5 indicates concern, > 2.0 is HIGH severity.

**Recommendation:** Dynamic scheduling or work stealing between workers.

### 3. CM Particle Overhead (Expected: MEDIUM)

Center-of-mass (CM) particles representing hierarchical groups require additional processing (group management, SDAR integration).

**Metric threshold:** CM time ratio > 30% indicates concern.

**Recommendation:** CM-specific optimization or separate CM task queue.

## Recommended Optimization Approach for v2.3

Based on ABYSS architecture and expected profiling results:

### Primary Focus: Work Distribution

1. **Implement work stealing** — Allow idle workers to steal tasks from busy workers
2. **Neighbor-count-aware scheduling** — Pre-sort particles by neighbor count, distribute to balance expected work
3. **Dynamic task sizing** — Smaller tasks for dense regions, larger for sparse

### Secondary Focus: Queue Efficiency

4. **MPI message batching** — Bundle multiple particle assignments per message
5. **Prefetching** — Send next task before current one completes

### Tertiary Focus: Memory Optimization

6. **Improve data locality** — Sort particles by spatial proximity before processing
7. **Cache-blocking** — Process particles in cache-friendly chunks
