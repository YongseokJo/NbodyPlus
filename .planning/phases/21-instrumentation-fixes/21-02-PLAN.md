## Objective

Improve cache statistics handling when hardware performance counters (perf_event) are unavailable. This addresses FIX-04.

## Background

HPC systems typically restrict `perf_event_open()` syscall for security reasons. The current implementation silently fails and reports `counters_available = false`. This plan enhances the fallback behavior to provide clearer messaging and optional timing-based estimation.

<task id="6" type="code">
Add method to compute timing-based estimates.

Add to Profiler class public methods:

```cpp
    // Phase 21: Compute memory estimates from timing when counters unavailable
    void computeCacheEstimates(double force_loop_time_s, long long particles_processed,
                               long long total_neighbors) {
        if (interval_cache_stats_.counters_available) return;  // Use real data if available

        // Estimate operational intensity
        // Each particle-neighbor pair: ~30 FLOPs (distance, force, accumulation)
        // Each particle-neighbor pair: ~48 bytes read (2 particles * 24 bytes pos/vel)
        double flops = total_neighbors * 30.0;
        double bytes_accessed = total_neighbors * 48.0;

        if (force_loop_time_s > 0) {
            double gflops = flops / force_loop_time_s / 1e9;
            interval_cache_stats_.estimated_memory_bandwidth_gb_s = bytes_accessed / force_loop_time_s / 1e9;
            interval_cache_stats_.estimated_operational_intensity = flops / bytes_accessed;
            interval_cache_stats_.estimates_computed = true;
        }
    }
```
</task>
