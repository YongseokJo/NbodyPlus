## Objective

Integrate the AVX-512 vectorized force kernel into `compute_acceleration_irr()` to replace the scalar neighbor loop. This plan modifies the hot path identified in Phase 9.

## Context

Plan 10-01 created the `simd_force.h/cpp` module with:
- `NeighborBatch` struct for pre-gathered neighbor data
- `gather_neighbor_data()` for collecting active neighbor data
- `compute_force_avx512()` for vectorized force calculation
- `compute_force_scalar()` for fallback

Now we integrate this into the actual irregular force calculation in `compute_acceleration_irr()`.

<task id="2">
Modify `compute_acceleration_irr()` to use vectorized force calculation for the neighbor loop.

**Current code structure (lines ~105-168):**
```cpp
PROFILE_START(TimerID::IrregularNeighborLoop);
for (int i=0; i<this->num_neighbors; i++) {
    ptcl = &particles[neighbors[this->neighbors_offset + i]];
    // ... scalar force calculation
}
PROFILE_STOP(TimerID::IrregularNeighborLoop);
```

**Replace with:**
```cpp
PROFILE_START(TimerID::IrregularNeighborLoop);

// Pre-gather neighbor data into aligned buffers
NeighborBatch batch;
gather_neighbor_data(particles, neighbors, this->neighbors_offset, this->num_neighbors,
                     new_time, batch);

// Compute forces using vectorized kernel
double a_nb[3] = {0.0, 0.0, 0.0};
double adot_nb[3] = {0.0, 0.0, 0.0};

#ifdef __AVX512F__
compute_force_avx512(pos, vel, batch, a_nb, adot_nb);
#else
compute_force_scalar(pos, vel, batch, a_nb, adot_nb);
#endif

// Accumulate into temporary acceleration
for (int dim = 0; dim < DIM; dim++) {
    a_tmp[dim] += a_nb[dim];
    adot_tmp[dim] += adot_nb[dim];
}

neighbor_pairs = batch.count;

PROFILE_STOP(TimerID::IrregularNeighborLoop);
PROFILE_WORK(TimerID::IrregularPairsEvaluated, neighbor_pairs);
```

**Important:** The original loop also handles:
1. CM particle set building (`CMPtclsSet.insert()`) - This needs to be preserved
2. New members detection (`if (sqrt(r2) < r_search && vx < 0)`) - This needs to be preserved

Either:
a) Add this logic to the gather phase, or
b) Keep a separate loop for these bookkeeping operations

Recommendation: Add CM particle tracking to gather_neighbor_data(), but handle new_members separately since it needs the computed distance. Modify gather to return cm_particles set.
</task>

<task id="4">
Handle the new_members detection that was in the original neighbor loop.

The original code checked:
```cpp
if (sqrt(r2) < r_search && vx < 0)
    this->new_members[this->new_num_members++] = ptcl->particle_index;
```

Options:
a) Store r2 and vx in NeighborBatch and check after force calculation
b) Separate pass for new_members detection
c) Move new_members detection into gather phase using pre-predicted positions

Implement option (a) or (b) - the simplest approach that preserves correctness.

For option (b), add a small loop after force calculation:
```cpp
// Check for new members (used for few-body search)
for (int i = 0; i < batch.count; i++) {
    double dx = batch.pos_x[i] - pos[0];
    double dy = batch.pos_y[i] - pos[1];
    double dz = batch.pos_z[i] - pos[2];
    double dvx = batch.vel_x[i] - vel[0];
    double dvy = batch.vel_y[i] - vel[1];
    double dvz = batch.vel_z[i] - vel[2];
    double r2 = dx*dx + dy*dy + dz*dz;
    double vx = dx*dvx + dy*dvy + dz*dvz;
    if (sqrt(r2) < r_search && vx < 0) {
        this->new_members[this->new_num_members++] = batch.indices[i];
    }
}
```

This requires adding `indices[]` array to NeighborBatch to track which particle each slot corresponds to.
</task>
